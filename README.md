# Квадрок

Двумерная кроссбраузерная игра на движке Defold, адаптированная под мобильные устройства.

## Механика

- Игровое поле — квадрат условных клеток, сетка не рисуется. Игра начинается
  с поля **16 × 16**, а после каждой победы открывается следующий уровень:
  **16 → 18 → 20 → 21 → 23 → 25**. Максимальный размер — **25 × 25**.
  Перечень уровней задаёт `M.LEVELS`, текущий размер хранится в `M.FIELD_SIZE`
  и применяется через [`M.set_field_size()`](main/game.lua), границы роста —
  `M.MIN_FIELD_SIZE` и `M.MAX_FIELD_SIZE`, следующий уровень вычисляет
  [`M.next_field_size()`](main/game.lua).
- Когда пройдено **максимальное поле** (25 × 25), размер больше не растёт:
  сложность увеличивается **целью партии** — нужно разобрать на **100 кубиков
  больше** за каждый следующий круг (значение [`M.total_cells()`](main/game.lua),
  счётчик кругов — `M.EXTRA_ROUNDS`, шаг — `M.EXTRA_CELLS_PER_ROUND`).
- В **центре поля** находится стартовый квадрат, выделенный контуром: **4 × 4**
  на полях 16–20 и **5 × 5** на полях 21–25 (порог переключения —
  `M.ZONE_SWITCH_SIZE`). Именно в нём появляются новые детали: в стартовом
  квадрате **4 × 4** — только **тетромино** (4 кубика), а в стартовом квадрате
  **5 × 5** равновероятно выпадают **тетромино** (4 кубика) и **пентамино**
  (5 кубиков) — случайной формы и случайного поворота.
- Игрок **тапом захватывает** фигуру и **тащит её в любом направлении** пальцем
  (мышью на десктопе). Точное попадание в клетку фигуры не требуется: достаточно
  тапнуть в любую клетку стартового квадрата (зоны появления) — фигура будет
  захвачена. Пока фигура в руке, её положение **квантизуется по клеткам**:
  она перескакивает из клетки в клетку, оставаясь под пальцем.
- Отпущенная фигура **остаётся на поле**, только если она **касается границы поля
  или другой ранее поставленной фигуры**. Иначе она **улетает обратно в центр**
  зоны появления.
- Во время перетаскивания фигура окрашена обычным цветом, если её можно оставить,
  и приглушённым, если опоры нет. Подсказка внизу экрана тоже меняется.
- Контур центрального квадрата — **запретная зона**: ставить фигуру поверх зоны
  появления нельзя, она не удержится и вернётся в центр. Зона всегда остаётся
  свободной для следующей фигуры.
- **Ряд или столбец**, полностью заполненный без пробелов, **убирается с поля**,
  а все его кубики засчитываются как разобранные ([`M.clear_lines()`](main/game.lua)).
  Кубики убираются **каскадом**: по одному (слева направо для ряда, сверху вниз
  для столбца) они улетают в центр поля, уменьшаются и растворяются. Счётчик
  «Разобрано» увеличивается после завершения анимации, тогда же появляется
  следующая деталь; ввод в это время игнорируется.
- После уборки линии оставшиеся кубики **сдвигаются к ближайшей стороне поля**
  ([`M.collapse()`](main/game.lua)). Сдвигается только **связная группа,
  примыкающая к удалённой линии**: кубик за пробелом остаётся на месте.
  Например, если удалён второй ряд сверху, а в столбце есть кубики в 3-м и
  4-м ряду и пусто в 5-м, то они переезжают во 2-й и 3-й ряд, а пустота
  остаётся ниже. Сдвиг сопровождается короткой анимацией.
- Цель партии — разобрать **`S × S × 2 / 4`** кубиков, где `S = M.FIELD_SIZE`
  (при поле 16 × 16 это `128`, при 25 × 25 — `312`). Значение хранится
  в `M.TOTAL_CELLS` и пересчитывается при смене размера поля.
- Партия заканчивается в двух случаях:
  - **Некуда поставить новую деталь** (занята зона появления или для детали нет
    ни одной позиции с опорой) — появляется табличка
    **«Не беда, попробуй снова»**, тап начинает ту же партию заново;
  - **Разобрано всё запланированное количество кубиков** — появляется табличка
    **«Получилось! Ну тогда усложняем»**, открывается следующий уровень
    (18, 20, 21, 23 → 25), достигнутый размер **сохраняется на устройстве**.
    На поле 25 × 25 табличка сообщает, что достигнут максимум.
- Прогресс (достигнутый размер поля) сохраняется на устройстве через
  `sys.save`/`sys.load` ([`main/progress.lua`](main/progress.lua)): на десктопе
  и мобильных это файл в папке приложения, в HTML5 — файл в IndexedDB. Путь
  всегда берётся из `sys.get_save_file("kvadrok", "kvadrok_progress")`: только
  он указывает внутрь постоянного хранилища (в HTML5 — `/data/.kvadrok/`),
  поэтому прогресс переживает перезагрузку страницы. После запуска игра
  продолжается с сохранённого поля.

## Счётчики

Сверху экрана выводится надпись **«Осталось разобрать N кубиков»** — сколько
кубиков ещё нужно убрать до победы (счётчик уменьшается). Внизу — **«Разобрано
K кубиков»** — сколько кубиков уже убрано с поля. Оба счётчика обновляются в
[`update_hud()`](main/game.gui_script) и склоняют слово «кубик» по числу.

Контур стартового квадрата плавно меняет цвет в зависимости от текущего
заполнения игрового поля в процентах — [`M.fill_ratio()`](main/game.lua):

- до **30 %** — зелёный → жёлтый (чистый жёлтый на 30 %);
- **30–70 %** — жёлтый → красный;
- выше **70 %** — чистый красный.

Процент в интерфейсе не выводится — только цвет контура.

## Призовые кубики

В жёлтой и красной фазе (контур жёлтый или красный, заполнение от 30 %)
каждые **4 хода** в случайной заполненной клетке появляется призовой кубик —
золотой или серебряный. Он переливается и блестит: цвет медленно «гуляет»
волной, а по клетке бежит узкий блик. Призовой кубик — украшение уже занятой
клетки, поэтому он не занимает места и не влияет на сбор линий.
Одновременно на поле может быть **не больше 5** призовых кубиков: пока лимит
исчерпан, новые не появляются (`BONUS_MAX = 5`).

Срок жизни не ограничен: кубик **остаётся призовым до тех пор**, пока его не
уберёт собранная линия. Тогда он улетает в центр поля вместе с остальными
кубиками и даёт **один из двух призовых эффектов** — какой именно, выбирается
случайно при сборе линии. Эффект действует на следующую фигуру, пока игрок её
не захватит:

- **Вращение** — фигура поворачивается на **90° каждые полсекунды**. Поворот
  настоящий: меняются сами клетки фигуры (форма и габариты), поэтому после
  захвата фигура **фиксируется в том положении, в котором её взял игрок**.
- **Перебор** — фигура в стартовом квадрате **раз в секунду заменяется
  другой случайной**, пока игрок не тапнет. В момент тапа фиксируется именно
  та деталь, которая была на экране.

Захваченная фигура больше не вращается и не перебирается — ведёт себя как
обычная.

Поворот клеток реализован чистой логикой в [`main/game.lua`](main/game.lua):
[`M.rotate_cells()`](main/game.lua) и [`M.rotate_piece()`](main/game.lua).

Константы в [`main/game.gui_script`](main/game.gui_script):
`BONUS_INTERVAL = 4`, `BONUS_MAX = 5`, `BONUS_SPIN_STEP_DELAY = 0.5`,
`BONUS_SHUFFLE_STEP_DELAY = 1.0`, `BONUS_FILL_MIN = 0.3`.

## Управление

- Тап по стартовому квадрату в центре (в любую его клетку, не обязательно
  точно по фигуре) — захват фигуры.
- Перетаскивание пальцем — фигура двигается по клеткам в любом направлении.
- Отпускание — фигура фиксируется при наличии опоры (край поля или другая фигура),
  иначе плавно возвращается в центр зоны.
- Тап после окончания игры: после поражения — та же партия заново, после
  победы — следующий уровень (поле больше на 2 клетки), а после победы на
  максимальном поле — новый круг с целью на 100 кубиков больше.
- Мышь на десктопе работает так же, как касание (одинаковое действие `touch`).

## Отрисовка

Поле рисуется **одной динамической текстурой** (`gui.new_texture` + `gui.set_texture_data`),
которая пересобирается при каждом ходе. Это обходит ограничение GUI на количество узлов
(512 по умолчанию) и даёт стабильную производительность на мобильных устройствах: 256–625
клеток (16 × 16 … 25 × 25) не превращаются в отдельные узлы.

Размер текстуры — `S × 8` пикселей по каждой стороне, где `S = M.FIELD_SIZE`
(при 16 × 16 это 128 пикселей, при 25 × 25 — 200), одна клетка = 8 × 8 пикселей.
Текстура создаётся **для каждого размера поля** отдельно и кэшируется, поэтому при
переходе на следующий уровень размер буфера и клетки пересчитываются.
Сетка не рисуется: пустые клетки — ровный фон, клетки зоны — чуть светлее.
Фиксированные фигуры записываются в эту же текстуру, поэтому поле обновляется
одной операцией `gui.set_texture_data`.

В логике ряд `0` — нижний, а строки буфера текстуры идут сверху вниз, поэтому
[`build_buffer()`](main/game.gui_script:158) перебирает ряды в обратном порядке.
Иначе поле рисуется зеркально по вертикали: фигура после отпускания «перепрыгивает»
выше или ниже точки, где её оставили.

Контур центрального квадрата рисуется отдельными GUI-боксами (4 полосы + слабый
ореол снаружи), поэтому его цвет можно менять каждый кадр без пересборки текстуры.
Толщина линии — ровно **1 игровой пиксель**, то есть 1 пиксель текстуры поля
(`1/8` клетки): линия лежит на пиксельной сетке и остаётся тонкой на любом экране.
Полосы контура не перекрываются, а ореол начинается снаружи линии, поэтому в углах
нет двойной прозрачности и светлых «пятен».

Текущая фигура в руке рисуется отдельными GUI-боксами — по одному на клетку
(заливка + подсветка верхней грани). Их позиции обновляются при перетаскивании,
поэтому деталь двигается по клеткам поверх текстуры поля, а её цвет сообщает,
можно ли её отпустить.

## Масштабирование

Пропорции игрового поля не зависят от разрешения и масштаба экрана — при изменении
размера окна они **не меняются**, а свободное место остаётся полями по краям:

- Вся геометрия задаётся в эталонных единицах сцены `BASE_W × BASE_H` (420 × 800,
  как в [`game.project`](game.project)) и не зависит от фактического размера окна.
- Все GUI-узлы создаются с `gui.ADJUST_FIT`: движок масштабирует их **единым
  коэффициентом** по меньшей стороне окна, поэтому квадрат поля не превращается
  в прямоугольник на экранах с другими пропорциями.
- Поле всегда квадратное; его сторона считается от эталонной сцены как
  `min(доступная ширина, доступная высота)`.
- Отступы интерфейса заданы в долях от эталонной сцены (`MARGIN_TOP_R`, `MARGIN_BOTTOM_R`,
  `MARGIN_SIDE_R`), а не в абсолютных пикселях.
- Контур — линия толщиной 1 пиксель текстуры поля (`FRAME_T`, `gp = cell / CELL_PX`),
  ореол — одно кольцо шириной `3` игровых пикселя (`FRAME_GLOWS`), а не в долях клетки.
- Клетки фигуры — отдельные GUI-боксы размером с клетку поля, поэтому фигура
  масштабируется вместе с полем и свободно перетаскивается.
- Шрифт HUD масштабируется пропорционально стороне поля (`gui.set_scale`).
- Координаты касаний переводятся в систему сцены через `gui.screen_to_local()`:
  движок отдаёт `action.x/y` растянутыми на всё окно, что не совпадает с визуальным
  положением узлов при `ADJUST_FIT`. Поэтому [`touch_xy()`](main/game.gui_script:479)
  берёт экранные координаты и снимает поля (letterbox) и масштаб автоматически.
- При отпускании детали её позиция не пересчитывается по координатам события
  `released`: фиксируется уже достигнутая квантизованная клетка, иначе деталь
  «прыгала» бы перед фиксацией.

На портретных разрешениях поле занимает одинаковую долю экрана и не выходит за отступы.
На широких экранах (например, 1600 × 500) поле уменьшается по высоте и центрируется,
оставаясь квадратным; на вытянутых по вертикали — по ширине. Пересчёт выполняется
в [`relayout()`](main/game.gui_script:254) при старте и по сообщению `window_resized`.

## Темы оформления

В правом верхнем углу сцены есть кнопка переключения темы с подписью, на
которую тему она переключит (**«Светлая тема»** / **«Темная тема»**). Выбор
сразу применяется ко всем элементам и сохраняется на устройстве, поэтому
после перезапуска игра открывается в последней выбранной теме.

- Темы описаны таблицей `THEMES` в [`main/game.gui_script`](main/game.gui_script):
  фон приложения, фон поля и зоны появления, палитра фигур, цвет текста,
  плашек окончания партии, кнопки и подсветки рядов/столбцов.
- В светлой теме фон приложения светлый, шрифты тёмные, а фигуры насыщеннее
  и ярче — иначе они терялись бы на белом поле.
- Фон приложения `background_color` в [`main/game.gui`](main/game.gui) не задан:
  цвет задаётся сообщением `clear_color` в `@render:`, поэтому тема меняет
  его без пересборки GUI.
- Пиксельная текстура поля и цвета узлов детали пересобираются при смене темы
  (`prepare_blocks()`, `prepare_piece_colors()`), кэши подсветки сбрасываются.
- Кнопка работает всегда, в том числе во время анимаций и после окончания
  партии: это настройка оформления, а не игровое действие.

## Настройки

- [`main/game.lua`](main/game.lua): `M.LEVELS` — размеры поля по уровням
  (`16, 18, 20, 21, 23, 25`), `M.MIN_FIELD_SIZE` — стартовый размер (16),
  `M.MAX_FIELD_SIZE` — максимальный размер (25), `M.ZONE_SWITCH_SIZE` — поле,
  до которого стартовый квадрат 4 × 4 (20), `M.FIELD_SIZE` — текущий размер,
  `M.TOTAL_CELLS` — базовая цель партии (`S × S × 2 / 4`), действующая цель —
  [`M.total_cells()`](main/game.lua), `M.EXTRA_CELLS_PER_ROUND` — прибавка к
  цели за круг на максимальном поле (100), `M.EXTRA_ROUNDS` — сколько таких
  кругов пройдено, `M.ZONE` — сторона стартового квадрата (4 или 5),
  `M.TOUCH_DIAGONAL` — считать ли касание углом опорой для фигуры.
- [`main/game.gui_script`](main/game.gui_script): `FILL_WARN` (0.3) и
  `FILL_BAD` (0.7) — опорные точки заполнения поля (доля занятых клеток),
  по которым [`frame_color()`](main/game.gui_script) считает цвет контура
  (зелёный → жёлтый → красный).
- [`main/progress.lua`](main/progress.lua): `M.APP_ID` — идентификатор
  приложения для `sys.get_save_file` (`kvadrok`), `M.FILE` — имя файла
  сохранения прогресса (`kvadrok_progress`), `M.KEY` — ключ с достигнутым
  размером поля, `M.KEY_ROUNDS` — ключ с числом пройденных кругов на
  максимальном поле, `M.KEY_THEME` — ключ с выбранной темой (`dark`/`light`).
  `M.save_progress()` и `M.save_theme()` дописывают значения в один файл,
  не затирая друг друга.
- [`main/game.gui_script`](main/game.gui_script): `THEMES` — палитры тёмной и
  светлой тем (фон приложения, фон поля и зоны появления, цвета фигур, текста,
  плашек, кнопки и подсветки рядов), кнопка в правом верхнем углу
  (`THEME_BTN_*`) переключает тему и сохраняет выбор в `progress.save_theme()`.
- [`game.project`](game.project): портретная ориентация 420 × 800, `html5.scale_mode = fit`,
  `gui.max_count = 2048`.
- [`input/game.input_binding`](input/game.input_binding): `TOUCH_MULTI` маппится на
  действие `touch`, `MOUSE_BUTTON_1` — на отдельное действие `mouse`. В
  [`on_input()`](main/game.gui_script) способ управления запоминается в
  `self.input_mode` (`"touch"` или `"mouse"`) по последнему событию.
- [`main/game.gui_script`](main/game.gui_script): `DRAG_LIFT_R` / `DRAG_LIFT_MIN_CELLS` —
  насколько деталь поднимается над пальцем при захвате. Подъём применяется только
  для касания (иначе палец закрывает деталь); при управлении мышью деталь
  остаётся под курсором без смещения.

## CI и деплой

Сборка и развёртывание выполняются в GitHub Actions на **self-hosted** раннере
(`runs-on: [self-hosted]`), на котором установлен Docker. Контейнер игры
запускается на Docker-демоне раннера (реальная машина), поэтому продолжает
работать после завершения workflow.

### Почему bob.jar не скачивается с d.defold.com

Прямое скачивание `bob.jar` (~230 МБ) с `d.defold.com` на этом хосте идёт
десятки-сотни байт в секунду, из-за чего сборка падала по таймауту. Решение
(взято из проекта `bumpy`):

1. `bob.jar` один раз публикуется ассетом GitHub Release с тегом
   `bob-jar-<sha1>` — GitHub отдаёт его быстро;
2. образ-сборщик (`docker/bob-builder.Dockerfile`) скачивает `bob.jar` из этого
   релиза (резерв — `d.defold.com` с жёстким лимитом скорости);
3. образ-сборщик публикуется в GitHub Container Registry, и во время деплоя он
   только скачивается (`docker pull`) — ни `docker build` образа-сборщика, ни
   загрузок с `d.defold.com` в деплое нет.

Движки HTML5 (`libexec/wasm-web`) лежат **внутри** `bob.jar`, поэтому при сборке
бандла в сеть никто не ходит.

### Workflow

| Файл | Триггер | Назначение |
| --- | --- | --- |
| [`.github/workflows/fetch-bob.yml`](.github/workflows/fetch-bob.yml) | вручную | Скачать `bob.jar` стабильной версии Defold и приложить к релизу `bob-jar-<sha1>`. |
| [`.github/workflows/build-bob-image.yml`](.github/workflows/build-bob-image.yml) | вручную | Собрать образ-сборщик (JDK 25 + `bob.jar` + библиотеки X11/GL) и опубликовать в `ghcr.io/<owner>/kvadrok-bob-builder:<sha1>`. |
| [`.github/workflows/deploy-master.yml`](.github/workflows/deploy-master.yml) | push в `main`, вручную | Собрать HTML5-бандл (`wasm-web`), упаковать в nginx-образ и развернуть контейнер `kvadrok-web` на порту `8098`. |

### Первичная настройка (один раз)

1. **Раннер**: на машине с Docker зарегистрировать self-hosted раннер
   репозитория (`Settings → Actions → Runners → New self-hosted runner`) и
   запустить его как службу. В проекте он установлен в
   `~/actions-runner-kvadrok` и работает через systemd user unit
   `kvadrok-runner.service` (включён `loginctl enable-linger`, иначе служба
   останавливается при выходе пользователя):
   ```bash
   systemctl --user enable --now kvadrok-runner.service
   ```
2. **bob.jar в релизе**: Actions → **Fetch bob.jar (manual)** → Run workflow.
   Без этого шага образ-сборщик будет тянуть `bob.jar` с медленного
   `d.defold.com`.
3. **Образ-сборщик**: Actions → **Build & Publish bob-builder image** →
   Run workflow. Тег — sha1 стабильной версии Defold (см.
   `https://d.defold.com/stable/info.json`). Повторять при обновлении Defold.

После этого каждый push в `main` собирает и переразворачивает игру:
`http://<хост-раннера>:8098/`.

### Локальная проверка в Docker

```bash
# 1. Образ-сборщик (bob.jar берётся из релиза bob-jar-<sha1>)
docker build \
  --build-arg BOB_SHA1=d295ed4edff2e49072719835713e625f409849f1 \
  --build-arg BOB_RELEASE_REPO=comse31/kvadrok \
  -f docker/bob-builder.Dockerfile \
  -t kvadrok-bob-builder:25-jdk .

# 2. HTML5-бандл (--architectures wasm-web: только однопоточный движок,
#    иначе bob полезет за wasm_pthread-web на d.defold.com)
docker run --rm --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -v "$PWD":/project -w /project kvadrok-bob-builder:25-jdk \
  java -jar /opt/bob/bob.jar --root . --platform wasm-web \
    --architectures wasm-web --archive --variant release \
    --bundle-output dist/web resolve build bundle

# 3. nginx-образ и запуск
docker build -f docker/Dockerfile -t kvadrok-web:test .
docker run --rm -p 8098:80 kvadrok-web:test
# открыть http://localhost:8098/
```

`docker/nginx.conf` отдаёт `.wasm` с `Content-Type: application/wasm` (без
этого браузер не запускает движок) и сжимает `.js`/`.html`.

Для сборки через Defold API редактора используется
`POST http://127.0.0.1:<порт>/bob` (порт — в `.internal/editor.port`, токен — в
`.internal/editor.token`) с телом:

```json
{
  "options": {
    "platform": "wasm-web",
    "architectures": "wasm-web",
    "archive": true,
    "variant": "release",
    "bundle-output": "dist/web",
    "root": "."
  },
  "commands": ["resolve", "build", "bundle"]
}
```

Обратите внимание: `architectures` передаётся строкой. Массив `["wasm-web"]`
bob отклоняет (`Invalid bob option supplied`).
